# 見た目の確認手順

自動テストで見ていない範囲を人が確認するための手順（Issue #96）。

## なぜこの手順が要るのか

`apps/web/test/` のテストは **CSS の宣言と、部品が出しているクラスの対応** を見ている。
実際に描画したときの折り返し・はみ出し・要素の重なりは見ていない。

Issue #86 のテストは 363 件が通っていたが、実機ではリンクが紫のまま、ヘッダが 3 行に
潰れ、コメント欄の textarea が 3 行分の幅しか無かった（#93）。**テストが通ったことを
もって「見た目は壊れていない」と判断すると、この形の見落としが繰り返される。**

視覚回帰テスト（描画結果を画像で比較する）は入れていない。理由は
`apps/web/test/style-coverage.test.tsx` の冒頭に書いた（要約すると、
#94 / #95 でデザインが固まる前に入れると差分だらけで機能しないため）。
**その代わりがこの手順書なので、見た目に触る変更ではこれを実施すること。**

## いつ実施するか

`globals.css` を変更したとき、または画面に出る要素の構造（`className` / タグ）を
変更したとき。CSS に触っていない変更では不要。

## 確認軸

実機またはブラウザの開発者ツールのデバイスモードで、以下の組み合わせを見る。

### 1. 幅 360px（狭い画面）

`@media (max-width: 480px)` の分岐より下。#93 で壊れていた症状はすべてこの幅で出た。

- [ ] **横スクロールが出ない** — ページを左右に振っても本文の幅が変わらないこと。
      長い URL を含むコメントがある Issue で確認する（スペースを含まない文字列は
      `overflow-wrap` が無いと要素を押し広げる）
- [ ] **ヘッダが 2 行以内に収まる** — 「World Issue Tracker」「Issue を起票」が
      単語の途中で割れていないこと。項目の単位で折り返すのは正しい
- [ ] **入力欄が本文の幅いっぱいに広がる** — 起票フォーム（`/issues/new`）、
      コメント欄（Issue 詳細）、一覧の絞り込み（`/issues`）の 3 箇所すべて。
      textarea が数文字分の幅で出ていないこと
- [ ] **枠を持つまとまりの中身が潰れていない** — Issue カード・コメントカードの
      文字が画面幅の半分近くまで押し込まれていないこと

### 2. 幅 1024px 以上（広い画面）

- [ ] 本文が `max-width: 800px` で中央に収まり、極端に間延びしていないこと

### 3. 日本語 / English の切り替え

ヘッダの言語切り替えで両方を見る。**片方でしか確認しないと、もう片方の文字列長で
崩れる**（日本語は単語区切りが無く、英語は語が長い）。

- [ ] 日本語でヘッダ・ボタン・ラベルが折り返して潰れないこと
- [ ] English でも同じこと（`Report an issue` のように語が長くなる）

### 4. キーボードのみで操作する

マウスを使わず Tab キーだけで一巡する。

- [ ] **いまどこにいるかが常に見える** — リンク・入力欄・ボタンのすべてで
      フォーカスの枠（outline）が出ること。枠が出ない要素があれば、その要素は
      キーボード利用者から見えていない
- [ ] Tab の移動順が画面の並び順とおおむね一致していること

### 5. リンクの色

- [ ] **未訪問と訪問済みが同じ色** — 一覧から Issue を数件開いてから一覧に戻り、
      開いたリンクだけが紫（ブラウザ既定）になっていないこと
- [ ] リンクが本文と区別できること（色だけでなく下線でも判別できる状態か）

### 6. タッチ端末

Android / Chrome など実機で。デバイスモードでは再現しない。

- [ ] **タップした要素の hover が残らない** — リンクをタップして戻ったときに、
      そのリンクだけ背景色が付いたままになっていないこと

## 崩れを見つけたときは

その症状を **自動で拾えないか** をまず考える。`apps/web/test/style-coverage.test.tsx` と
`apps/web/test/layout-integrity.test.tsx` は「指定が存在するか」を静的に見ており、
「指定を書き忘れた」型の崩れはそこに足せる。

拾えない型（実際の折り返し・重なり）だったときは、この手順書に確認軸として足す。
**手順書に足さずに直すと、次の変更で同じ崩れが戻る。**
